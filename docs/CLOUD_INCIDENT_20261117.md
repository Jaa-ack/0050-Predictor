## Supabase可行性

技術上可連接，但目前沒有因容量不足而需要緊急移轉，也未連接或上傳本次供應商資料至Supabase。2026-11-17查核官方免費方案為500MB資料庫配額、1GB檔案儲存與5GB一般對外流量；不是無上限備援。[官方方案](https://supabase.com/pricing)

免費Storage單檔上限50MB，原始SQLite快照須先壓縮並視結果分塊；無法直接把目前約240MiB快照當成一個未壓縮物件上傳。[官方檔案限制](https://supabase.com/docs/guides/storage/uploads/file-limits)

可行設計是保留本機正在採集與發報所需的熱資料，於關鍵窗口後非同步壓縮、分塊上傳至私人Storage；Postgres保存小型預測、評估與歸檔索引。必須有失敗重試、物件摘要、還原驗證及剩餘額度檢查；未驗證遠端可還原前不得刪除本機唯一副本，掛載遠端Storage也不是現有SQLite可直接使用的本機檔案系統。私人bucket提供存取控制，資料不得以公開bucket或公開連結發佈。[官方私人bucket文件](https://supabase.com/docs/guides/storage/buckets/fundamentals)

逐筆同步遠端請求仍會消耗解析、序列化、網路往返與本機緩衝資源，可能增加發報延遲；即使免費容量足夠，也不能以它替代本次吞吐與發布期限的修正驗證。接入前仍需選定使用者所屬專案、剩餘額度、地區與僅伺服器端可讀的私人憑證；不新增付費方案、不在網站或對話收集金鑰。

# 操作與故障排查

## 日常順序

1. 確認合法還原行情及來源可用時間，匯入完整歷史快照。
2. 執行 `research`，先查看成本後表現與 logistic／Ridge 基準；資料／程式／設定封存。
3. 凍結設定後執行 `holdout`。若看過答案後改模型，需要新的未看過測試或等待新資料。
4. 以 `predict --paper` 或 `daily --paper` 逐日記錄；維持固定版本的研究程序。
5. 每日新行情到達，`settle` 只評分已到期的1／5／20日預測。檢查 Brier、MAE、覆蓋率及資料缺漏。
6. `daily --paper` 會產生重新訓練及校準的新候選版本，不改寫舊預測。
7. 正式啟用前 `promote` 檢查門檻；`predict` 不帶 `--paper` 僅能使用已通過的正式預測模型。

## 常見情況

| 情況 | 處理 |
|---|---|
| FinMind 400／403 還原行情無權限 | 設定具權限 `FINMIND_TOKEN`，或匯入具可靠 `adj_close` 的 CSV；不以 raw close 假裝還原價格 |
| 402／429 配額／流量限制 | 等待配額恢復、降低請求；保留原始錯誤；不產生補造行情 |
| `insufficient history` | 保留126日測試後仍須有足夠訓練、校準及20日成熟標籤；下載更長歷史。短程工程測試可明確縮小設定，但不得提高可行性證據 |
| `Price feed stale`／缺最新目標 | 檢查開休市、資料商延遲、停牌及更新失敗；系統不沿用舊價當作新價 |
| `Postclose model requires...` | 指定最新交易日20:00之後截止時間；盤前使用另訓練的 preopen 模型 |
| `Preopen session is unverified` | 透過 `calendar --csv` 匯入核實日曆；不要用一般工作日日曆代替交易所日曆 |
| 外部特徵缺少／過期 | 提供與訓練相同欄位的最新事件資料。缺值或過久未更新的必需外部因子會標示 abstain；目前通用120日上限仍需按頻率細分 |
| `Model was fitted after...` | 重建該歷史時點可得的訓練版本，不用現在模型假裝當時模型 |
| `forecast is immutable` | 同一股票／決策／期間／版本的內容變更被拒絕；使用新版本保留修正歷史 |
| 校準覆蓋率不佳 | 比較各市場狀態，使用成熟樣本建立新候選；不能直接把已發出的區間擴到覆蓋答案 |
| `Code changed since seal` | 不對已改動的程序沿用未開封協定。先重新封存開發設定，並記錄曾看過的測試期間 |
| promote 被阻擋 | `status` 列出資料品質、十年基準、樣本外／保留測試、60日影子紀錄等具體未達條件 |

## 新增資料源

只要能提供具時區的發布與可用時間，可以先將數值資料轉成長表事件 CSV：`ticker,feature,value,period_end,published_at,available_at,version`。`ticker=*` 表示全球共用因子。修正數據追加新版本，不覆蓋舊事件。重新研究後產生新的特徵結構／程序版本。

新聞原文、夜盤合約歸屬、美股夏令時間、分析師預期及公告修正都應在資料源模組先處理，不能只用日期合併。詳見 GAPS.md 的資料驗收條件。

## 備份與復原

完整備份所選 root，包含 raw、snapshots、runs、current/champion 指標及 SQLite 帳本。停止寫入後複製，或使用 SQLite backup 介面，避免只複製正在寫入的單一資料庫檔。不要刪除舊快照來節省空間，除非確定所有引用其版本的模型、預測與稽核都已另行封存。

## 排程

預設不啟用背景工作。範本在臺北時區20:15執行，仍須確認當日交易與資料已完整發布。盤前另以08:30、獨立根目錄及模型執行。金鑰從 `.env`／環境注入，排程輸出保存在使用者指定的本機日誌位置。沒有券商連線或自動發送訊息。
